# Политика безопасности (Security Policy)

## Поддерживаемые версии

Проект находится на ранней стадии разработки (`0.1.x`). Исправления безопасности применяются к ветке `main` и последнему тегированному релизу.

| Версия | Поддержка |
| --- | --- |
| `main` (`0.1.x`) | Да |
| `< 0.1.0` | Нет |

## Как сообщить об уязвимости

**Не публикуйте уязвимости, эксплойты, токены или секреты в публичных GitHub Issues и Pull Requests.**

Сообщайте о проблемах конфиденциально через:

- **GitHub Private Vulnerability Reporting:**  
  https://github.com/NoVate911/NexDeck/security/advisories/new

В отчёте желательно указать:

- затронутый компонент (`core`, `transport`, `api`, `approval`, `plugin_engine`, `desktop`, `mobile`);
- шаги воспроизведения;
- возможное влияние (обход авторизации, повторное использование запроса, выход из песочницы плагина и т. д.);
- предложения по исправлению, если есть.

## Границы безопасности проекта

- **Windows UAC:** подсистема `Remote Approval` подтверждает только прикладные и разрешённые действия NexDeck и **не заменяет/не обходит штатный Windows UAC**.
- **Universal API и Remote Approval:** обязательны аутентификация клиента, минимальные права доступа (`deny-by-default`), одноразовый `request_id` и ограниченный таймаут.
- **Изоляция плагинов:** расширения запускаются в песочнице WebAssembly с квотами памяти, времени выполнения и CPU.
- **Контроль зависимостей:** все внешние крейты проходят проверку `cargo-deny` (уязвимости RustSec и совместимость лицензий с `Apache-2.0`).
