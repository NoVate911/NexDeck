# План тестирования NexDeck

Каждое изменение в проекте должно подтверждаться автоматическими проверками на всех уровнях.

---

## 1. Уровни проверок

| Уровень | Что проверяется | Когда запускается |
| --- | --- | --- |
| **Стиль и статический анализ** | `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `RUSTDOCFLAGS="-D warnings" cargo doc` | Локально и в каждом PR (`ci.yml`) |
| **Unit-тесты** | Доменная логика, валидация, очереди, state machine подтверждений | Каждый PR (`ci.yml`) |
| **Интеграционные тесты** | Межкрейтовые сценарии в `tests/integration/` | Каждый PR (`ci.yml`) |
| **Безопасность и зависимости** | `CodeQL (rust)`, `cargo-deny` (RustSec + Apache-2.0), `Dependency Review`, `Secret Scan` | Каждый PR и еженедельно (`security.yml`) |
| **Smoke-сборка** | Релизная сборка и запуск `--version` на `windows-latest` и `ubuntu-latest` | Каждый PR (`ci.yml`) и релизы (`release.yml`) |
| **Профилирование ресурсов** | Замер idle RAM (цель 2–5 МБ) и CPU на release-сборке Windows 11 | С Этапа 1 |
| **Мобильные и UI-тесты** | `flutter test` и интеграционные проверки клиента | С Этапа 2 |

---

## 2. Ключевые инварианты по модулям

- **`crates/approval`:** запрет повторного использования `request_id` (replay), отклонение просроченных запросов и недопустимых действий, независимость от UAC.
- **`crates/api`:** отказ отозванным и неавторизованным клиентам, проверка лимитов таймаута и входных полей.
- **`crates/notifications`:** ограниченная ёмкость очереди сна без утечек памяти, фильтрация по приоритету и источнику.
- **`crates/plugin_engine`:** валидация манифеста и потолков квот; с Этапа 6 — принудительное прерывание зависших WASM-модулей.
- **`crates/transport`:** переходы состояний и валидация фреймов `Envelope`; с Этапа 1 — восстановление соединения после разрыва и сна ПК.
