# ADR-0005: Сетевой стек Core Agent (`tokio + axum + rustls`) и сопряжение устройств

- **Статус:** Принято
- **Дата:** 2026-11-17

## Контекст

На Этапе 1 требуется надёжный сервер для Wi-Fi WebSocket-подключения мобильного клиента, а на Этапе 4 — локальный HTTP/WebSocket-интерфейс Universal API, при сохранении минимального потребления памяти (цель 2–5 МБ RAM в простое) и шифрования локального трафика.

## Решение

1. Использовать **`tokio`** (однопоточный `current_thread` runtime в минимальной конфигурации по умолчанию) и **`axum`** с поддержкой WebSocket.
2. Защитить Wi-Fi-транспорт поверх **WSS** (`rustls` с самоподписанным сертификатом хоста и пиннингом SHA-256 отпечатка сертификата на мобильном клиенте).
3. Выполнять первичное сопряжение через одноразовый PIN/QR-код с обменом на постоянный `device_token`, который хранится на хосте только в виде криптографического хэша (SHA-256).

## Последствия

- **Плюсы:** единый серверный фундамент для транспорта и будущего Universal API без дублирования HTTP/WS-стеков, шифрование трафика в локальной сети без облака и центральных CA.
- **Минусы:** бинарный файл немного крупнее по сравнению с голым `tungstenite`; подключение `rustls` (`ring`) потребует явного описания лицензии в `deny.toml`.
