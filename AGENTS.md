# Инструкции для AI-агентов (AGENTS.md)

Этот файл задаёт обязательные правила работы для любого AI-агента, подключающегося к разработке **NexDeck**.

---

## 1. Порядок начала работы (читать в первую очередь)

Перед любыми правками агент **обязан** последовательно изучить:

1. `AGENTS.md` — правила работы, ограничения и процессы.
2. [`JOURNAL.md`](JOURNAL.md) — актуальный статус проекта, следующие задачи и известные ошибки/ограничения (чтобы не повторять их). При необходимости исторического контекста — [`docs/journal/archive/`](docs/journal/archive/README.md).
3. Целевые документы этапа:
   - [`docs/architecture/overview.md`](docs/architecture/overview.md) — архитектура и зависимости модулей;
   - [`docs/architecture/requirements.md`](docs/architecture/requirements.md) — требования и технические ограничения;
   - [`docs/architecture/roadmap.md`](docs/architecture/roadmap.md) — план этапов (0–7), критерии MVP и открытые вопросы;
   - [`docs/architecture/testing-plan.md`](docs/architecture/testing-plan.md) и [`docs/security/threat-model.md`](docs/security/threat-model.md).

## 2. Языковая политика

- **Основной язык проекта — русский:** `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md`, `JOURNAL.md`, `docs/`, тексты Issue и Pull Request (заголовки и описания) пишутся **на русском**.
- **Английский язык используется только там, где того требуют стандарты разработки:**
  - исходный код на Rust/Dart (`crates/`, `apps/`), идентификаторы, имена типов, публичные doc-комментарии;
  - сообщения коммитов по формату **Conventional Commits** (`feat(core): ...`, `fix(api): ...`);
  - ключи конфигураций (`.github/workflows/*.yml`, `Cargo.toml`, `deny.toml`) и юридический текст `LICENSE` (`Apache-2.0`);
  - англоязычное зеркало [`docs/README.en.md`](docs/README.en.md).

## 3. Процесс разработки (Git Flow & Pull Requests)

1. **Issue перед кодом:** каждая задача начинается с привязанного GitHub Issue (или создания нового).
2. **Ветвление от `main`:** прямой `push` в `main` запрещён. Рабочие ветки создаются с префиксами:
   - `feature/<name>`, `fix/<name>`, `refactor/<name>`, `docs/<name>`, `test/<name>`, `ci/<name>`.
3. **Маленькие атомарные коммиты:** формат Conventional Commits (на английском), одна логическая задача на один PR.
4. **Обязательное обновление журнала:** **каждый PR** обязан обновить [`JOURNAL.md`](JOURNAL.md) (актуальный статус, выполненная задача, следующий шаг, новые уроки/ошибки). При разрастании журнала устаревшие детали переносятся в `docs/journal/archive/`.
5. **Локальная проверка перед PR:** запускать `./scripts/verify.ps1` (или `./scripts/verify.sh`), не игнорировать предупреждения `clippy` и `rustdoc`.
6. **Оформление PR:** заполнять все поля [шаблона PR](.github/PULL_REQUEST_TEMPLATE.md) на русском языке со ссылкой `Closes #<id>`.
7. **Squash and Merge:** агент имеет право самостоятельно выполнять **Squash and Merge** своего PR **только после успешного прохождения всех обязательных проверок CI и безопасности** (`CI Gate`, `CodeQL (rust)`, `Cargo Deny`, `Secret Scan`, `Dependency Review`) и при отсутствии конфликтов.

**Запрещено:** отключать проверки CI, обходить или ослаблять Rulesets/Branch Protection, форсировать push в `main`, изменять права доступа без разрешения владельца.

## 4. Архитектурные и ресурсные инварианты

- **Минимальное потребление (`Core Agent`):** фоновый процесс `nexdeck-agent` ориентируется на **2–5 МБ RAM в простое**, минимальную нагрузку на CPU и не должен зависеть от GUI-фреймворков или WebView.
- **Стек компонентов:**
  - `crates/*` (`nexdeck-core` и подсистемы) — **Rust** (Edition 2024);
  - `apps/desktop` — чистый **Rust UI** (`egui` / `slint`, отдельный процесс через локальный IPC);
  - `apps/mobile` — **Flutter** (Android / iOS);
  - `crates/plugin_engine` — изолированный **WebAssembly** (`wasmtime` с жёсткими квотами памяти/CPU/времени);
  - `crates/transport` — абстракция над транспортом (MVP: Wi-Fi WebSocket; далее USB и Bluetooth).
- **Граница безопасности:**
  - удалённое подтверждение действий (`crates/approval`) **никогда не заменяет и не обходит штатный Windows UAC**;
  - все запросы имеют одноразовый `request_id`, привязку к приложению и ограниченный срок жизни;
  - сторонние приложения и плагины работают по принципу минимальных привилегий (deny-by-default).
- **Честность реализации:** не оставлять фиктивных заглушек, имитирующих готовую функциональность, и не скрывать незавершённые задачи.

## 5. Правила данных и безопасности

- **Только синтетические примеры:** все данные в тестах, примерах (`examples/`), конфигах и документации должны быть **вымышленными примерами** (например, `ExampleApp`, `org.example.*`, `example.invalid`, `req-example-1`). Допустимы только системные/стандартные сетевые значения (`localhost`, `127.0.0.1`, порты, стандартные пути Windows).
- **Никаких секретов:** запрещено коммитить токены, пароли, ключи, сертификаты, личные email и непроверенные бинарные файлы.
- **Лицензии:** проект под **Apache License 2.0**. Не добавлять зависимости с несовместимыми лицензиями (проверяется `cargo-deny`).
- **Локальные спецификации:** файл `TZ.md` не добавляется в Git-репозиторий и указан в `.gitignore`.

Существенные изменения архитектуры, стека, протоколов или безопасности требуют фиксации ADR в [`docs/architecture/adr/`](docs/architecture/adr/) и предварительного согласования с владельцем проекта.
